Fase 1 — Extração, Chunking e Indexação de Texto
O script começa montando o Google Drive e conectando na API de curadoria do Squad 01. Puxa todos os artigos catalogados (não só os aprovados) e salva em metadados_api.json no Drive. Depois lista os PDFs em PDFs não vetorizados/ e cruza com os metadados da API, mostrando um relatório: quantos têm match, quantos estão aprovados, pendentes, rejeitados ou sem match nenhum. Cada PDF no loop sabe se tem metadados e se foi aprovado.
Para cada PDF novo, lê os bytes do Drive e passa para o Docling com Tesseract OCR trilíngue (português, espanhol, inglês) e force_full_page_ocr=True. O Docling retorna dois outputs: a lista de blocos de texto (cada um com o número da página) e o objeto DoclingDocument (necessário para detectar figuras depois). Se falhar, tenta modo simples sem OCR e sem tabelas.
Os blocos passam por um pré-processamento de tabelas. A função converter_tabelas_em_blocos varre os blocos na ordem, detecta sequências de linhas markdown (|...|) e duplica: mantém o bloco original em markdown e adiciona um bloco convertido para texto descritivo ("Tabela com colunas: Dose, Prod. Dose 0: Prod = 18.2..."). Blocos de texto normal passam intactos.
Depois vem o chunking: concatena todos os blocos numa string contínua, mantendo um mapa de posição → página. Fatia em 1024 caracteres com 256 de overlap, cortando na última palavra ou quebra de linha (nunca parte uma palavra no meio). Cada chunk sabe de qual página veio (pela página com maior sobreposição no intervalo).
Antes de extrair imagens, verifica se o JSON de imagens já existe para aquele PDF. Se existe, pula (protege descrições do Gemini já feitas). Se não, itera os elementos do DoclingDocument na ordem de leitura, acumulando texto. Quando encontra um PictureItem, registra a página e guarda os últimos 800 caracteres como contexto textual. Renderiza cada página candidata inteira via PyMuPDF em 150 DPI e passa pelo filtro OpenCV de 3 camadas: a primeira verifica se >1.5% dos pixels têm cor (gráficos são coloridos, texto é preto), a segunda analisa a densidade de preenchimento dentro de cada blob grande (texto é esparso ~5-12%, figuras são densas >13%), e a terceira verifica a direção das bordas via Sobel (texto é horizontal, figuras têm bordas em todas as direções). Páginas que falham nas 3 camadas são deletadas. As aprovadas são salvas como PNG em data/Imagens/ com um JSON de metadados contendo o contexto textual e gemini_processado: false.
Cada chunk é vetorizado em batch pelo Qwen3-Embedding-0.6B (vetor denso de 1024 dimensões) e individualmente pelo OpenSearch Neural Sparse v2 (vetor esparso SPLADE). Os dois vetores são enviados ao Qdrant Cloud via REST direto com payload bibliográfico completo: content, tipo (texto/tabela), título, autores, ano, DOI, periódico, cultura, palavras-chave, nutrientes, ferramentas, resumo, página do PDF, nome do arquivo e timestamp.
No final, salva o PDF no indexados.json, move para PDFs concluídos/ e libera memória com gc.collect().

Fase 2 — Descrição de Imagens com Gemini Vision
O script é leve — só usa requests, sem modelos de ML. Começa com um reparo automático: varre todos os JSONs e reseta páginas que tinham erro 429 (rate limit) de execuções anteriores, removendo gemini_processado, gemini_erro e figuras. Assim essas páginas voltam a ser pendentes.
Para cada JSON em data/Imagens/, filtra as páginas com gemini_processado: false. Se todas já foram processadas, pula o arquivo.
Para cada página pendente, carrega o PNG, codifica em base64 e monta o prompt. O prompt é escolhido conforme tipo_conteudo: imagem, tabela ou misto. Cada variante pede ao Gemini 3.1 Pro extrações diferentes mas todos pedem: tipo da figura, título como aparece no PDF, descrição de 4-8 frases, variáveis com unidades, séries/tratamentos identificados pela legenda, todos os pontos de dados visíveis com valores numéricos, valor máximo e mínimo com números exatos, ponto ótimo se identificável, tendência matemática, equação de regressão se visível, significância estatística (letras a/b/c), e conclusão prática para recomendação agronômica. A temperatura é 0.1 e o maxOutputTokens é 8192.
O Gemini retorna um JSON com a lista de figuras. O script parseia, salva no JSON de metadados e marca gemini_processado: true.
Se der erro 429, o script não marca como processado. Salva o progresso parcial daquele PDF, espera 60 segundos e pula para o próximo PDF com break. Na próxima execução, as páginas pendentes serão reprocessadas. Erros permanentes (400, 500, JSON inválido) marcam como processado com o campo gemini_erro para não ficar tentando infinitamente.

Fase 3 — Vetorização de Descrições de Imagens
Carrega os mesmos modelos da Fase 1 (Qwen3 denso + OpenSearch esparso) mas não chama nenhuma API externa.
Para cada JSON, filtra páginas que atendam a duas condições: gemini_processado: true (Fase 2 já descreveu) e qdrant_vetorizado: false ou ausente (ainda não indexou). Páginas sem figuras são marcadas como feitas automaticamente. Páginas aguardando Gemini são contadas mas ignoradas.
Para cada figura descrita, monta um texto rico concatenando todos os campos: prefixo [IMAGEM - tipo], título da figura, descrição completa, variáveis, séries, até 20 pontos de dados extraídos formatados como texto, valores máximo e mínimo, ponto ótimo, tendência, equação de regressão, significância e conclusão.
Esse texto é vetorizado pelo Qwen3 (denso) e OpenSearch (esparso) e enviado ao Qdrant com payload contendo todos os campos estruturados do Gemini mais os metadados bibliográficos do artigo. O campo tipo: "imagem" diferencia dos chunks de texto e tabela.
Só marca qdrant_vetorizado: true quando todas as figuras de uma página são indexadas sem erro. Se falhar parcialmente, a página inteira é reprocessada na próxima execução.
